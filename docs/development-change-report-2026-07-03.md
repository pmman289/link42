# Link42 开发变更测试报告

日期：2026-07-03

## 版本

- Controller：0.5.12
- Agent：0.5.10
- Web：0.4.7
- Python package：0.2.1

## 本次主要变更

### 端口台账插件

- 移除旧的测试插件。
- 新增“端口台账”节点插件，用于记录节点对外入口端口占用情况。
- 用户可为每个节点维护一个可用入口端口范围，例如 `23000-23099`。
- 保存范围后可立即触发节点扫描，也可稍后手动扫描。
- 扫描会查找范围内正在监听的 TCP/UDP 端口，并额外识别 WireGuard：
  - `wg show all listen-port`
  - `wg-quick` 配置中的 `ListenPort`
  - OpenWrt UCI `network.*.listen_port`
- 扫描结果只展示检测到的端口和来源，不自动填写用途，由用户确认后登记。
- 台账支持手动添加、删除、编辑用途，并支持按端口号、用途、协议、检测来源模糊搜索。

### 已修复测试反馈

- 修复 BIRD 编辑器内 `Ctrl+S` / `Cmd+S` 未触发保存的问题。
  - 原因：CodeMirror keymap 捕获了旧 render 的保存闭包，文件变脏后快捷键仍可能读到旧状态。
  - 处理：改为在编辑器外层捕获 `keydown`，使用当前 React 状态调用“保存并刷新”。

### 节点插件宿主

- 新增 Controller / Agent / Web 三端的节点插件框架。
- 节点详情页不再直接堆插件功能，改为“打开插件”按钮，插件在独立弹窗内按 tab 展示。
- 插件状态会同时检查 Agent 能力和最低版本，避免 UI 显示“可用”但真实任务无法执行。
- 插件任务状态查询已放到需要 Web 登录鉴权的 `/api/tasks/{task_id}`。
- 后端会拒绝对离线节点直接创建插件任务。

### BIRD 配置插件

- 新增 BIRD 配置编辑插件。
- Agent 可递归列出 `/etc/bird` 下的 `*.conf` 文件。
- 支持主配置：
  - `/etc/bird/bird.conf`
  - `/etc/bird.conf`
- 不再把 `/etc/bird/envvars` 当作 BIRD 配置文件编辑。
- 读取配置时保留原始内容，不会 strip 文件末尾换行。
- 校验配置时会恢复原文件内容和 metadata，避免 validate 改变 mtime。
- 批量保存前会检查所有文件：
  - 文件被其他人修改：拒绝保存，不写入任何文件。
  - 文件被其他人删除：拒绝保存，不写入任何文件。
  - 重复提交同一文件：拒绝保存。
- 批量保存时会先写入全部变更，再执行 `bird -p -c <main config>` 校验。
- 保存并刷新时会执行 `birdc configure`。
- `birdc configure` 失败时会恢复本次写入的文件，并把错误返回给前端弹窗。

### BIRD 配置编辑 UI

- 打开 BIRD 插件后会自动读取配置树。
- 配置树改为手动展开的树状文件管理器。
- 打开文件时有加载提示，并防止继续点击其他文件。
- 已读取文件会缓存在前端，多个文件来回切换不会丢失未保存内容。
- 保存按钮会一次性保存所有已修改文件。
- `Ctrl+S` / `Cmd+S` 会保存全部修改。
- 文件树会标记：
  - 已缓存
  - 已修改
- 有未保存修改时，关闭插件、切换 tab、刷新配置树、离开页面都会提示确认。
- 点击“刷新配置树”确认放弃修改后，会立即清空草稿，保存按钮不会短暂可用。
- 编辑器改为 CodeMirror，支持：
  - 语言模式切换
  - 行号
  - 折行
  - 代码折叠
  - 自动补全
  - 搜索
- 修复 CodeMirror 输入区域鼠标指针、搜索面板样式异常等问题。
- 插件任务成功用提示展示，错误用弹窗展示，不再直接向用户展示原始任务 JSON。

## 版本兼容性说明

- `node_plugin.bird.apply` 和 `node_plugin.bird.apply_many` 的最低 Agent 版本已提升到 0.5.9。
- 0.5.8 Agent 不具备本次要求的 “保存后必须执行 birdc configure，失败恢复文件” 语义。
- `node_plugin.port_inventory.scan` 的最低 Agent 版本为 0.5.10。
- 测试 BIRD 保存和端口台账扫描功能时，请确保节点 Agent 已升级到 0.5.10。

## 观察项说明

- BIRD 配置校验失败或应用失败时，Agent 任务状态可能仍是 `succeeded`，业务结果中会返回 `applied:false`、`valid:false`、`restored:true` 等字段。
- Web 前端已按业务结果判断失败并显示错误弹窗。
- 直接调用 API 的测试脚本或第三方调用方需要同时检查任务状态和 `result.applied` / `result.valid`，不能只看 AgentTask 的 `status`。

## 建议测试范围

### 插件入口

1. 选择在线节点。
2. 点击节点详情里的“打开插件”。
3. 确认插件弹窗打开，能看到 BIRD 配置和端口台账 tab。
4. 离线节点应无法执行插件任务。

### 端口台账

1. 打开端口台账插件。
2. 填写端口范围，例如 `23000-23099`。
3. 保存范围后确认是否立即扫描。
4. 扫描结果应列出范围内监听的 TCP/UDP 端口和 WireGuard 监听端口。
5. 从扫描结果点击“登记”，用途应为空，用户可自行填写。
6. 手动添加一个 TCP/UDP 端口条目。
7. 添加重复协议和端口时应提示已存在。
8. 删除条目后列表应立即更新。
9. 搜索端口号或用途，应能过滤台账记录。

### BIRD 配置树

1. 打开 BIRD 配置插件。
2. 确认自动读取配置树。
3. 确认目录需要手动展开。
4. 确认只显示可编辑 BIRD 配置文件，不显示 `/etc/bird/envvars`。

### 多文件缓存编辑

1. 打开文件 A，修改但不保存。
2. 打开文件 B，修改但不保存。
3. 切回文件 A，确认修改仍在。
4. 文件树应显示已缓存/已修改状态。
5. 点击保存，应一次性保存所有修改文件。

### 异常场景

1. 打开文件后，在节点上手动修改该文件，再从面板保存。
   - 预期：保存失败，提示文件已被其他人修改。
   - 预期：不会写入其他待保存文件。
2. 打开文件后，在节点上删除该文件，再从面板保存。
   - 预期：保存失败，提示文件已删除或移动。
3. 提交错误 BIRD 配置。
   - 预期：`bird -p` 校验失败，文件被恢复。
4. 构造 `birdc configure` 失败。
   - 预期：保存失败，文件被恢复，弹窗显示 `birdc configure` 错误。

### UI 交互

1. 有未保存修改时关闭插件弹窗，应提示是否放弃。
2. 有未保存修改时切换插件 tab，应提示是否放弃。
3. 有未保存修改时点击刷新配置树，应提示是否放弃。
4. 确认刷新后，“保存并刷新”按钮不应短暂可用。
5. 在编辑器里 `Ctrl+F` 搜索面板应正常显示。
6. 在编辑器里 `Ctrl+S` 应触发保存全部修改。
