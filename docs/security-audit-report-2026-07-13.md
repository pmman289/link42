# Link42 安全审计报告

## 1. 报告信息

- 审计日期：2026-07-13
- 审计版本：`0b35d56fb1321630cd8d2a88af4da4bfc1a3f421`
- 审计范围：主控 API、Web 面板、节点 Agent、部署脚本、发布与升级链路、依赖清单及受版本控制的文档
- 审计方法：人工静态审查、信任边界与数据流分析、目录穿越定向验证、凭据扫描、依赖审计及现有自动化测试
- 代码变更：无；本文件仅记录问题和修复要求

## 2. 执行摘要

本次审计确认 8 项需要开发修复的问题，其中 4 项高危、4 项中危（1 项仅影响暴露的开发环境），另有 3 项纵深防御建议。

最紧急的问题是 3 个完整 Agent Token 已进入受版本控制的文档及 Git 历史。无论对应环境是否仅在内网使用，都必须按凭据已泄露处理。主控还会长期明文保存 Agent Token 和 WireGuard 密钥，而高权限 Agent 使用控制器任务字段构造文件路径时缺少独立校验。这些问题会显著放大仓库、数据库、主控或任务通道失陷后的影响。

项目负责人已明确接受以下设计风险，因此不计入待修复问题：

- 公开访客可以通过 Looking Glass 节点探测节点可达网络。
- 主控与 Agent 部署可以使用明文 HTTP。

上述风险应继续在部署文档中明确说明，使运营人员理解系统的信任模型。

## 4. 详细问题

### L42-SEC-001：Agent 凭据进入代码仓库和 Git 历史

风险等级：高危

状态：待修复，需立即执行凭据响应

#### 证据

受版本控制的运维文档中存在 3 个唯一且完整的 `l42agent_...` Token。其中至少一个 Token 与主控地址、节点 ID 一起出现在可直接执行的命令中。

- `docs/operations-notes.md` 第 28、30、31 行
- `docs/handoff-memory.md` 第 33、34、131 行
- `git log -S` 表明相关凭据出现在多个历史版本中

本报告有意不复述 Token 明文。

#### 影响

持有有效 Agent Token 的攻击者可以冒充对应节点，执行注册和心跳、拉取待执行任务、读取任务载荷中的配置或密钥，并伪造任务结果。伪造成功结果会使主控把实际未执行的配置操作记录为已成功部署。

仅删除当前文档中的行不能完成处置，因为凭据仍存在于 Git 历史、镜像、分支、缓存及既有克隆中。

#### 修复要求

1. 立即轮换全部 3 个已暴露 Agent Token，并验证旧 Token 无法继续认证。
2. 从当前文档删除凭据，替换为无法误认为真实值的占位符。
3. 在运营条件允许时重写受影响 Git 历史并更新公共镜像。历史清理不能替代 Token 轮换。
4. 在 pre-commit 和 CI 中加入自动凭据扫描，扫描范围必须包括 Markdown 和 Shell 示例。
5. 检查主控与 Agent 日志，确认相关节点是否出现异常来源或异常任务轮询。

#### 验收标准

- 使用每个已泄露 Token 请求 Agent API 均返回 `401`。
- 当前仓库和完整 Git 历史扫描不再发现非示例的 `l42agent_`、`l42web_` 或 `l42lg_` 凭据。
- CI 能阻止新生成的 Link42 Token 进入任意受版本控制文件。

### L42-SEC-002：Agent Token 和 WireGuard 密钥明文存储

风险等级：高危

状态：待修复

#### 证据

- `apps/api/link42_api/models.py:44-45` 同时保存 `agent_token_hash` 和 `agent_token_value`。
- `apps/api/link42_api/main.py:3634-3646` 将新生成的 Token 同时写入哈希列和明文列。
- `apps/api/link42_api/schemas.py:231-257` 在普通 `NodeRead` 响应中包含 `agent_token_value`，并非仅创建时返回。
- `apps/api/link42_api/models.py:80-81` 明文保存 WireGuard 私钥。
- `apps/api/link42_api/models.py:161-162` 明文保存预共享密钥。
- `apps/api/link42_api/models.py:94` 及任务载荷可能保留包含密钥的完整部署配置。
- 升级备份会完整复制包含上述数据的 SQLite 数据库。

这与 `packages/link42_common/security.py:10` 中“Token 仅创建时明文返回，服务端必须保存哈希”的安全约定直接冲突。

#### 影响

主数据库、WAL、升级备份、存储卷快照或节点列表 API 的读取权限一旦泄露，攻击者即可取得所有被保存的 Agent Token 和 WireGuard 密钥。Agent Token 可用于节点冒充；WireGuard 静态私钥和预共享密钥可用于端点冒充、建立未授权的未来隧道会话及主动中间人攻击。静态密钥泄露不等同于可直接解密过去已抓取的 WireGuard 流量。

#### 修复要求

1. 从数据库模型及所有普通响应模型中删除 `agent_token_value`。
2. Agent Token 仅允许在创建或轮换响应中返回一次。手工重装应要求显式轮换或使用短期注册 Token，不能重新读取旧 Token。
3. 使用带认证的信封加密保护 WireGuard 私钥、预共享密钥及含密钥配置字段。
4. 加密主密钥必须独立于数据库及其备份保存，并使用严格文件权限或密钥管理服务。
5. 提供数据迁移：加密现有 WireGuard 密钥并清除明文 Agent Token。现有 Agent Token 应执行轮换。
6. 审查节点、任务状态和配置相关响应，避免不必要地返回密钥。

#### 验收标准

- 数据库导出中不存在可直接使用的 Agent Token、WireGuard 私钥或预共享密钥。
- `GET /api/nodes` 和 `GET /api/nodes/{id}` 不返回 Agent 凭据。
- 密文认证失败或主密钥不可用时，解密操作必须失败关闭。
- 数据库备份中不包含加密主密钥。

### L42-SEC-003：Agent 任务路径存在目录穿越

风险等级：高危

状态：待修复

#### 证据

主控 Pydantic 请求模型会校验接口名，但以 root 权限运行的 Agent 没有对收到的任务载荷执行独立校验。

- `apps/agent/link42_agent/system.py:245-275` 使用 `Path(wireguard_dir) / f"{interface_name}.conf"` 构造并写入文件。
- `apps/agent/link42_agent/system.py:334-387` 在接口改名清理中重复相同模式。
- `apps/agent/link42_agent/system.py:411-428` 和 `519-546` 在读取、删除时使用相同构造。
- `apps/agent/link42_agent/gre.py:56-59` 和 `149-174` 使用未经 Agent 校验的任务字段构造 GRE 路径。

定向临时目录验证确认：`interface_name="../outside"` 会逃出 WireGuard 配置根目录，并在其父目录写入 `outside.conf`。构造更深的相对路径可以指向以 `override.conf` 结尾的 systemd 服务 drop-in。

#### 影响

任何获得主控任务、主控存储或任务响应控制权的攻击者，都可以让 Agent 在 `/etc/wireguard` 或 GRE 目录之外写入或删除 root 所有的 `.conf` 文件。这可修改系统服务或其他安全敏感配置，并可能形成持久化 root 代码执行。

主控侧校验不能替代 Agent 校验，因为 Agent 才是执行高权限操作的安全边界。

#### 修复要求

1. 在 Agent 端增加共享接口名校验器，遵守 Linux 长度限制并使用字符白名单，例如 `^[A-Za-z0-9_.-]{1,15}$`，同时显式拒绝 `.` 和 `..`。
2. 在每次读取、写入、备份或删除前解析配置根路径和目标路径，并要求目标是根目录的严格子路径。
3. 对 WireGuard、GRE、中间层实例名、旧接口名及服务单元名应用等价校验。
4. 防止符号链接穿越；在已验证目录内使用原子写入或替换，并拒绝异常符号链接。
5. 增加直接调用 Agent handler 的测试，覆盖目录穿越、绝对路径、超长名称、Unicode 混淆字符和服务名载荷。

#### 验收标准

- Agent handler 直接拒绝 `../x`、`/absolute`、`.`、`..`、包含路径分隔符及超过平台长度限制的名称。
- 所有拒绝用例均无法在临时受管根目录之外创建、读取、修改或删除文件。
- 即使绕过主控模型，Agent 仍会独立执行相同校验。

### L42-SEC-004：Agent 安装器在无法校验完整性时继续安装

风险等级：高危

状态：待修复

#### 证据

`deploy/sh/link42-agent.sh:323-336` 使用 `|| true` 忽略 `.sha256` 文件下载失败。如果校验文件为空或不可用，脚本会记录“跳过校验”，随后继续以 root 权限安装下载的二进制或源码包。

校验和与资产来自同一分发源，因此单独使用相邻 SHA256 文件也无法抵御分发源被攻陷。

#### 影响

校验文件发布错误、镜像不完整、发布源被攻陷或分发路径被篡改时，未验证代码可能在所有接入节点上以 root 权限安装并启动。

#### 修复要求

1. 无法下载或验证校验和、签名时必须终止安装。
2. 使用独立保护的发布密钥签署 manifest 或资产，安装器通过内置公钥验证签名。
3. 源码包解压前必须完成验证，并检查压缩包成员中的绝对路径、`..`、符号链接及硬链接越界。
4. 特权无人值守安装应使用不可变的版本化资产，避免依赖可变的 `latest`。
5. 发布 CI 应从节点实际使用的公开 URL 下载资产并验证签名与哈希。

#### 验收标准

- 完整性元数据缺失、格式错误或不匹配时，在解压或替换前终止安装。
- 同时替换资产及其相邻 SHA256 文件也无法通过签名验证。
- 恶意压缩包成员无法在解压目录之外写入文件。

### L42-SEC-005：管理员密码使用快速、无盐 SHA-256

风险等级：中危

状态：待修复

#### 证据

- `packages/link42_common/security.py:14-16` 为 Token 定义单次 SHA-256。
- `apps/api/link42_api/main.py:327-329`、`3399-3402`、`3465-3467` 将同一函数用于管理员密码。

SHA-256 适合对高熵随机 Token 做索引式哈希，但不适合作为密码哈希：它没有每个密码独立的盐，并且设计目标是高速计算。

#### 影响

数据库泄露后，弱密码或复用密码可被通用硬件高速离线尝试。初始密码为随机值只能降低首次部署风险，不能保护用户之后在设置中选择的密码。

#### 修复要求

1. 使用维护良好的密码库及 Argon2id，并为每个密码生成独立随机盐。
2. 在存储值中保留算法、版本和参数信息。
3. 在旧 SHA-256 密码下一次成功登录时迁移，或强制管理员重置密码。
4. 将 Token 哈希与密码哈希拆分为不同 API，避免再次误用。

#### 验收标准

- 新建及修改后的密码保存为带独立盐和参数的 Argon2id 哈希。
- 完成迁移后数据库中不存在旧 SHA-256 管理员密码哈希。
- 密码验证通过密码库 API 完成。

### L42-SEC-006：认证接口缺少限流和请求体上限

风险等级：中危

状态：待修复

#### 证据

- `POST /api/auth/login` 没有按账号或来源限制失败尝试。
- `apps/api/link42_api/main.py:687-727` 的全局中间件未限制请求大小或频率。
- `apps/api/link42_api/main.py:3484-3488` 在执行 3 MiB Logo 限制前先调用 `await request.body()`，此时完整请求体已进入内存。
- 公开登录及 Agent 接口依赖 FastAPI 常规请求体解析，没有应用层或反向代理请求体限制。

#### 影响

未认证客户端可以持续尝试管理员密码，也可以通过超大请求体消耗 worker 内存和连接容量。Agent 接口在端点 Token 校验前就会解析请求体，因此无需知道有效 Token 即可造成解析成本。

#### 修复要求

1. 在反向代理或 ASGI 中间件设置较小的全局请求体上限，并按端点设置更严格限制。
2. 文件上传改为流式读取，超过上限后立即停止。
3. 按账号及可信来源标识限制登录失败次数，并使用有上限的指数退避。
4. 对公开 Agent 和集成接口增加保守的频率、并发及队列限制。
5. 仅在明确配置的可信反向代理后接受转发来源 IP 头。

#### 验收标准

- 超大请求返回 `413`，且服务端不会先缓存完整请求体。
- 连续登录失败返回 `429`，并在文档规定时间后恢复。
- 直连部署下伪造 `X-Forwarded-For` 无法绕过限制。

### L42-SEC-007：Web 会话无有效期并持久化到 localStorage

风险等级：中危

状态：待修复

#### 证据

- `apps/api/link42_api/main.py:399-405` 只验证单个会话哈希，没有签发时间、空闲超时、绝对有效期或设备信息。
- `apps/api/link42_api/main.py:3403-3405` 创建会话时不设置有效期。
- `apps/web/src/main.tsx:503-512` 每次请求从 `window.localStorage` 读取 Bearer Token。
- `apps/web/src/main.tsx:2838` 登录后将 Token 持久化到 localStorage。

#### 影响

Web Token 泄露后会一直有效，直到注销、修改密码或新的成功登录覆盖它。localStorage 中的 Token 可被同源脚本读取，会放大未来 XSS 或前端依赖失陷的影响。

#### 修复要求

1. 使用服务端会话记录，包含签发时间、空闲超时、绝对有效期、吊销状态和最后使用信息。
2. 优先使用 `Secure`、`HttpOnly`、`SameSite` Cookie；或只在内存保存短期访问 Token，并设计受保护的刷新机制。
3. 若采用 Cookie 认证，必须同时增加 CSRF 防护并将通配 CORS 改为明确来源。
4. 增加严格的 Content Security Policy 和常用浏览器安全响应头。
5. 允许管理员查看和吊销活动会话。

#### 验收标准

- 已过期或已吊销会话即使 Token 正确也返回 `401`。
- 认证凭据不再能通过 `window.localStorage` 或 `window.sessionStorage` 读取。
- 自动化测试覆盖会话超时、吊销和密码变更后的失效行为。

### L42-SEC-008：锁定的 Vite 和 esbuild 版本存在已知漏洞

风险等级：暴露开发环境时为中危，生产静态构建为低危

状态：待修复

#### 证据

`npm audit --omit=dev` 报告 1 个高危和 1 个中危依赖：

- `vite` 5.4.21：开发服务器目录穿越和文件泄露公告，包括 `GHSA-fx2h-pf6j-xcff`
- `esbuild` 0.21.5：开发服务器跨站请求及响应读取，`GHSA-67mh-4wv8-2f99`

锁定版本位于 `apps/web/package-lock.json:1896` 和 `2672`。

生产控制器仅提供编译后的静态资源，不运行 Vite 服务器，因此生产影响有限。当 `vite dev` 或 `vite preview` 暴露给不可信网络时，漏洞仍可被利用。

#### 修复要求

1. 将 Vite 及实际解析的 esbuild 升级到兼容的已修复版本。
2. Vite 默认仅监听回环地址，禁止向不可信网络暴露开发或预览服务器。
3. 将仅用于构建的包移动到 `devDependencies`，使生产依赖审计准确反映运行时风险。
4. 在 CI 中运行依赖审计，并为仅影响构建环境的问题建立例外流程。

#### 验收标准

- `npm audit` 不再报告上述公告。
- 生产镜像只包含编译后的前端资产，不启动或暴露 Vite 服务器。
- 升级后前端构建和端到端测试通过。

## 5. 纵深防御建议

### L42-HARD-001：不要在长期日志中保留初始密码

`apps/api/link42_api/main.py:317-336` 会把初始管理员密码写入主控日志。这是当前文档规定的引导方式，但容器日志和集中日志通常会在首次登录后长期保留。

建议改为权限受限的一次性引导文件、显式初始化命令或强制首次登录重置。至少应明确日志保留要求，并在管理员修改密码后确保初始凭据失效。

### L42-HARD-002：主控使用非 root 用户运行

`Dockerfile.controller` 未声明非 root `USER`，`deploy/systemd/link42-api.service` 也未设置 `User`、`Group` 或 systemd 沙箱参数。Agent 的网络管理操作需要高权限，但主控常规 API 运行不需要无限制 root 权限。

建议使用专用 UID/GID，仅允许访问数据、配置、Web 和发布目录；在兼容范围内增加 `NoNewPrivileges`、`PrivateTmp`、`ProtectSystem`、`ProtectHome` 及受限可写路径。

### L42-HARD-003：启动日志不要输出完整数据库 URL

`apps/api/link42_api/main.py:1207-1213` 会原样记录 `settings.database_url`。当前默认使用 SQLite，但未来 SQLAlchemy URL 可能包含数据库凭据。

建议只记录数据库类型及脱敏后的主机/库标识，并为结构化启动配置提供通用凭据脱敏函数。
