# IPv4 地址管理

主控 / Web `0.6.24` 新增此功能；沿用现有 Agent 任务协议，已有 `0.6.23` Agent 无需为地址台账升级。

点击页面工具栏的“IPv4 地址管理”，可查看主控已知的节点固定地址、WireGuard/GRE 接口、已部署配置、未完成任务和扫描候选中的 IPv4 占用。支持按 IP、节点、接口及备注搜索，也可按状态、节点和地址池筛选。搜索完整 IP 会同时显示覆盖它的预留网段；搜索 CIDR 会显示网段内的实际主机地址和相交预留。首屏概览按实际 IPv4 主机地址去重；台账保留不同配置快照和任务的来源记录。

界面分为“占用台账”“地址池”“外部预留”。地址池卡片可查看该池占用和空闲推荐，推荐预览不会分配地址。

自动读取的范围是主控已保存的数据：节点固定 IPv4、WG/GRE 期望配置、已部署配置、活跃任务以及 WG 扫描候选。节点公网或私网入口 IP 不视为内网地址分配；Agent 尚未上报的系统网卡或 Loopback 地址不会自动发现，请先人工登记。刷新台账读取主控最新记录，不会下发网络扫描任务。

## 建池与分配

系统不预置网段。先创建两类地址池：

- **节点地址池**：例如 `10.100.0.0/24`，推荐节点固定 `/32` 地址。
- **链路地址池**：例如 `10.101.0.0/24`，每条链路独占一个 `/30` 或 `/31`，默认 `/30`。`/30` 推荐中间两个地址；`/31` 两个地址均可使用。

所有节点共用一个 IPv4 地址空间，地址池不能重叠。地址池 CIDR 必须填写网段地址，例如 `10.100.0.0/24`。

在新建或编辑节点时登记“固定内网 IPv4”；在 WireGuard/GRE 表单中选择“复用节点固定 /32”或“分配链路专用地址”，然后点击填入或推荐。也可手工填写地址，保存时同样查重。推荐会保留表单中的 IPv6 地址。

推荐结果暂不占用地址，关闭表单不会留下分配。真正保存时才进行事务内确认；其他人先保存了同一地址时，系统返回占用归属，重新推荐即可。

节点固定地址只维护台账，不会通过 Agent 配置 Loopback 或系统网卡。请自行在节点系统配置这些地址。

## 冲突与外部占用

同一个 IPv4 主机地址即为重复，与掩码无关：`10.100.0.1/24` 和 `10.100.0.1/32` 不能分配给不同节点；`10.100.0.2/24` 是另一个地址。

明确登记为节点固定地址的 `/32` 可以在该节点多条隧道复用。链路专用地址不能复用；位于链路池中的专用地址会保留整个对齐的链路子网，包括 `/30` 的网络与广播地址。

“登记外部占用 / 预留网段”可以记录单个 IP 或 CIDR，必须填写用途或所属设备。推荐会跳过这些预留。GRE 明确填写的外部对端隧道地址也会登记为占用。WireGuard 的 AllowedIPs、GRE 路由和节点入口地址不视为本机隧道地址分配。

升级时自动登记既有配置，不修改地址；既有重复会显示“冲突”。仍可查看、导入或修改节点名称等信息，但包含冲突地址的新增分配及部署会被阻止。已有同节点 `/32` 复用，可通过登记该节点的固定地址明确用途。

台账只反映主控已知配置与人工登记，不进行网络探测。项目外已经使用的地址应先手工登记。

## 改址与释放

改址时保留旧占用，直到真实部署成功并确认旧接口清理。停止接口、删除面板记录、清理失败、超时或 dry-run 都不会让地址立即变为空闲。

主机清理成功且没有其他引用时自动释放。双端链路必须等双方占用均释放后才回收整个子网。仅清理手工 GRE 本端不会释放外部对端。

保留主机配置的删除、节点固定地址及外部占用，需要确认原设备已经清理后点击“释放”。尚有有效配置引用或关联清理任务未完成时不能释放。相同接口的期望与已部署地址快照会一起解除，其他接口的引用仍保留。

扫描候选与导入后的接口会交接占用来源。清理已接管配置时也会移除对应的旧候选；如果有较新的扫描任务，则保留观察结果供确认，避免旧清理结果覆盖新状态。

## API 与实现

新增管理 API 均使用原有 Web 会话鉴权和 CSRF 规则：

| 路径 | 方法 | 用途 |
| --- | --- | --- |
| `/api/ipam/pools` | GET / POST | 列出、创建地址池 |
| `/api/ipam/pools/{id}` | DELETE | 删除无占用、无预留的地址池 |
| `/api/ipam/pools/{id}/recommend` | GET | 推荐节点地址或链路地址对，不写入占用 |
| `/api/ipam/inventory` | GET | `q` 搜索，`state` / `node_id` / `pool_id` 筛选，`offset` / `limit` 分页；附去重概览与节点选项 |
| `/api/ipam/check` | POST | 检查 IPv4 地址冲突 |
| `/api/ipam/reservations` | POST | 登记外部 IP 或预留 CIDR |
| `/api/ipam/claims/{id}/release` | POST | 确认清理后解除待释放占用 |
| `/api/ipam/reservations/{id}/release` | POST | 解除外部预留 |

释放请求必须包含 `{"confirmed_cleaned": true}`。

节点创建、编辑和读取增加 `internal_ipv4s`；编辑时省略字段保留旧值，传空列表解除登记并保留待确认占用。WireGuard/GRE 创建和编辑增加可选 `ipv4_link_pool_id`，指定时校验 IPv4 两端属于该池同一个合法链路子网。

IPAM 使用新增关联表，不改变原有节点入口字段。业务地址写入入口通过数据库分配锁串行化；最终配置、占用与任务在同一事务提交。独立的占用快照、配置实例标识和清理任务关联可在接口记录已删除后继续完成回收，并防止 SQLite 复用 ID 后迟到的旧任务影响新配置。心跳和任务轮询不经过 IPAM 分配锁。
